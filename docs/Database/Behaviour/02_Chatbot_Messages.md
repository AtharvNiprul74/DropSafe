# Table - chatbot_messages

**Schema:** Behaviour

**Version:** 1.0

**Status:** DRAFT

---

# Purpose

The `chatbot_messages` table stores individual messages exchanged during a DropSafe chatbot conversation.

Each message represents raw behavioural evidence.

Messages are preserved in their original form and may be consumed by AI feature engineering.

---

# Aggregate Owner

Behaviour Aggregate

---

# Template Type

Historical Entity

---

# Business Rules

- Every Message belongs to exactly one Conversation.
- Every Message has exactly one Sender Type.
- Messages are append-only.
- Original message content is never modified by AI.
- AI processing reads messages but never changes them.
- Message ordering is determined by `message_timestamp`.

# Columns

| Column | Type | Nullable | Description |
|---------|------|----------|-------------|
| id | UUID v7 | ❌ | Primary Key |
| conversation_id | UUID | ❌ | Conversation |
| sender_type | ENUM | ❌ | STUDENT, BOT, SYSTEM |
| message_text | TEXT | ❌ | Original Message Content |
| language | VARCHAR(20) | ✅ | Message Language |
| message_timestamp | TIMESTAMP | ❌ | Message Timestamp |
| created_at | TIMESTAMP | ❌ | Record Creation Timestamp |

---

# Business Constraints

- Every Message belongs to exactly one Conversation.
- Message text cannot be empty.
- Messages cannot be modified after creation.
- Messages are processed in chronological order.
- AI analysis must not alter the original message.

# Notes

Examples

Student message:

```
I am worried about my upcoming exams.
```

Bot message:

```
Would you like to discuss what is worrying you?
```

Student message:

```
I have failed two subjects already.
```

These messages are raw behavioural evidence.

This table never stores:

- Sentiment Score
- Stress Score
- Engagement Score
- Behaviour Score
- Risk Prediction
- AI Summary

Those values are generated by the AI Schema.
