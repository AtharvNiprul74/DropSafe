# Table - import_reports

**Schema:** Import

**Version:** 1.0

**Status:** DRAFT

---

# Purpose

The `import_reports` table stores the validation and processing result of an Import Session.

An Import Report provides a summary of what happened during an import, including records received, accepted, rejected, and the final import result.

It provides operational traceability without storing the complete source data.

---

# Aggregate Owner

Import Aggregate

---

# Template Type

Historical Entity

---

# Business Rules

- Every Import Report belongs to exactly one Import Session.
- An Import Session has at most one final Import Report.
- Import Reports are generated by the Import processing system.
- Import Reports are immutable after the Import Session is completed or failed.
- Rejected records are counted and summarized.
- Detailed row-level errors are stored separately from the summary when required.
- A PARTIAL_SUCCESS Import commits valid records while rejected records remain excluded from the committed dataset.
- A FAILED Import does not partially commit academic data.
- Row-level validation errors must be distinguished from fatal import errors.

# Columns

| Column | Type | Nullable | Description |
|---------|------|----------|-------------|
| id | UUID v7 | ❌ | Primary Key |
| organization_id | UUID | ❌ | Organization |
| import_session_id | UUID | ❌ | Import Session |
| total_records | INTEGER | ❌ | Total Records Received |
| valid_records | INTEGER | ❌ | Records Passing Validation |
| rejected_records | INTEGER | ❌ | Records Rejected |
| inserted_records | INTEGER | ❌ | New Records Created |
| updated_records | INTEGER | ❌ | Existing Records Updated |
| status | ENUM | ❌ | SUCCESS, PARTIAL_SUCCESS, FAILED |
| summary | TEXT | ✅ | Human-Readable Import Summary |
| generated_at | TIMESTAMP | ❌ | Report Generation Timestamp |

---

# Business Constraints

- Every Report belongs to one Import Session.
- Record counts cannot be negative.
- `valid_records + rejected_records` cannot exceed `total_records`.
- `inserted_records + updated_records` cannot exceed `valid_records`.
- A Report is generated only after validation or processing completes.
- Reports are immutable after generation.

---

# Error Handling

The report may contain a summary such as:

```text
13 records were rejected because of invalid student identifiers.
```

Detailed validation errors should be handled by the Import processing layer and should not be embedded as an unbounded JSON structure inside this table for Version 1.
